# 웹앱 상호작용 설계

까치 홈(폰에서 쓰는 앱)과 기기 페이지가 어떻게 움직이는지 적는다. 색, 글꼴, 간격 같은 시각 체계는 [DESIGN.md](../DESIGN.md), 기기 기능별 현황은 [sensors.md](sensors.md), 전체 구조는 [modules.md](modules.md)에 있다.

## 원칙

1. 글이 기본이고 말은 거든다. 받아쓴 말은 입력창에 들어가고, 확인하고 고친 뒤에 보낸다. 말하면 바로 보내는 방식은 인식이 자주 틀려서 쓰지 않는다.
2. 새 메시지가 먼저다. 답이 오는 중에 보내면 앞 턴을 멈추고 새 메시지를 처리한다. 30분 대화 정리와 사서 같은 백그라운드 작업도 멈춘다.
3. 기억은 조용히 한다. "노트에 적었어요" 같은 말 없이 반영하고, 무엇을 기억했는지는 답 아래 칩으로만 보인다.
4. 명령어가 없다. 끝내기, 되돌리기, 정정, 정리를 까치가 말의 의도로 판단한다.
5. 하는 일이 보인다. 도구를 쓰는 동안 무엇을 하는지 한 줄로 보여주고, 기기는 자기 화면에 지금 하는 일과 마지막으로 한 일을 띄운다.
6. 끊겨도 잃지 않는다. 앱이 잠깐 내려가도 서버는 턴을 끝까지 돌려 커밋하고, 앱은 돌아와서 이어 받는다.

## 화면

```
┌───────────────────────────────────┐
│                                   │
│                       내가 보낸 말  │  내 말풍선: 오른쪽, 채움
│ 까치의 답 (Markdown)                │  까치 말풍선: 왼쪽, 테두리
│ [노트 제목] [기억함: 건강]            │  출처 칩, 이번에 기억한 노트
│                 …                  │  이 화면의 대화, 최대 30턴
│       듣고 있어요. 다시 누르면 …     │  상태 줄 (할 말이 있을 때만)
│ [사진 썸네일 ×]                      │  보낼 사진 (있을 때만)
│ (사진) [ 메시지를 입력하세요 ] (마이크) (보내기) │
│ (≡)                                │  메뉴 버튼 (왼쪽 가장자리에서 밀어도 열림)
└───────────────────────────────────┘
```

화면은 대화 하나다. 까치 홈은 집에 늘 켜져 있는 까치를 어디서든 불러 쓰는 곳이라 대화가 중심이고, 나머지는 왼쪽에서 밀려 나오는 메뉴에 있다. 메뉴는 왼쪽 위 버튼을 누르거나 화면 왼쪽 가장자리에서 밀면 열리고, 손가락을 따라 움직인다. 다시 밀거나 바깥을 누르거나 Escape 로 닫는다. 메뉴 맨 위에는 기기와 대화 두 탭이 있다. 대화 탭에는 새 대화와 그 아래 지난 대화 목록이 있다. 목록은 Pi 세션 파일에서 읽고, 누르면 그 대화로 돌아가 이어서 말할 수 있다. 기기 탭에는 기기 추가와 기기 목록이 있다. 맨 아래에는 두 탭 모두 톱니바퀴 아이콘의 설정이 있다. 기기, 기기 추가, 설정은 메뉴에서 누르면 대화 위에 한 화면으로 열리고, 뒤로 가면 메뉴로 돌아온다. 팝업은 없다.

- 메뉴의 기기 탭은 안 쓰는 폰과 태블릿, 곧 기기의 목록이다. 까치 홈 자신은 목록에 없다. 줄마다 기기 모양 그림, 이름, 상태(켜져 있어요, 화면을 한 번 눌러야 해요, 꺼져 있어요), 불빛, 화살표가 있다. 화면을 한 번 눌러야 하는 기기는 불빛이 속 빈 초록 고리다. 허용을 기다리는 기기는 그 자리에 허용 버튼이 있다
- 기기 추가를 누르면 기기 추가 화면이 열린다. 기기에서 열 주소와 복사 버튼, 그리고 할 일 네 단계(주소 열기, 이름 붙이고 한 번 누르기, 여기서 허용, 화면 켜 두기)가 있다. 기기도 같은 Tailscale 계정에 로그인해 있어야 열린다
- 기기를 누르면 그 방의 "지금 이 방"을 읽어 온다. 밝기(카메라를 조도 센서처럼 써서 어두운지, 불이 켜졌는지, 되면 대략의 lux. 사진은 남지 않는다), 소리(조용해요, 보통이에요, 시끄러워요. 데시벨 숫자는 안 보임), 마지막으로 움직인 때, 놓인 자세와 방향, 위치(지도 버튼으로 연다)이고, 사진은 찍기 버튼을 눌러야 찍는다(뒤쪽 카메라, 저장 안 함). 사용자가 직접 보는 것이라 까치에게 닫아 둔 것도 읽히고, 기기 화면의 기록에 "까치 홈에서 읽었어요"로 남는다. 그 아래 "까치가 쓸 수 있는 것"에서 음성, 스피커, 조명(태블릿), 카메라, 소리 크기, 움직임 센서, 위치를 하나씩 열고 닫는다. 열어 두었지만 지금 쓸 수 없는 것은 스위치가 흐리다. 여기서만 정하고, 기기 화면에는 스위치가 없다. 새 기기는 모두 열려 있다. 맨 아래에 기기 삭제가 있다
- 예전에는 아래에 떠 있는 탭 막대로 화면을 오갔다(처음엔 입력, 출력, 연결, 에이전트, 설정 다섯, 다음엔 대화, 기기, 설정 셋). 막대가 입력창 바로 아래, 엄지가 닿는 자리를 차지해서 메뉴로 옮겼다. 연결(기기끼리 에이전트 없이 잇기)은 뺐다

위쪽 막대 오른쪽에는 집에 연결되는지가 보인다("집, 기기 2대 켜짐", 안 되면 "집에 연결할 수 없어요"). 앱을 열 때, 다시 앞으로 올 때, 30초마다 확인하고, 누르면 메뉴의 기기 탭이 열린다. 앱을 다시 열면 이어 가던 대화가 그대로 보인다. iOS 가 홈 화면 앱을 자주 닫아서다. 대화가 비어 있으면 가운데에 까치 아이콘과 "집에 있는 까치예요", 무엇을 할 수 있는지 한 줄이 보인다. 답하지 못한 턴에는 "다시 보내기" 버튼이 있다. 앱 다시 불러오기는 홈 화면 앱에 브라우저 새로고침이 없어서 설정 맨 아래에 둔다.

움직임은 어디서 왔는지와 눌린 것을 알리는 데만 쓴다. 메뉴는 왼쪽에서 미끄러져 나오고, 메뉴에서 연 화면은 오른쪽에서 들어온다. 스위치는 누른 자리에서 움직인다. 앱을 열 때는 아무것도 움직이지 않고, 기기의 동작 줄이기를 켜면 페이드만 남는다. 값은 [DESIGN.md](../DESIGN.md)의 What moves 에 있다.

## 보내기

입력창에서 Enter 는 보내기, Shift+Enter 는 줄바꿈이다. 한글을 조합하는 중의 Enter 는 보내기로 치지 않는다. 보내기 버튼은 글이나 사진이 있을 때만 눌린다.

### 받아쓰기

- 마이크를 누르면 듣기 시작하고 다시 누르면 멈춘다. 0.4초 넘게 누르고 있다가 떼면 뗄 때 멈춘다. 0.3초보다 짧은 누름은 무시하고, 60초가 넘으면 스스로 멈춘다
- 컴퓨터에서는 입력창 밖에서 Space 를 누르고 있는 동안 받아쓴다
- 누르기 직전 0.17초 정도를 함께 보내서 첫 음절이 잘리지 않게 한다
- 받아쓴 말은 입력창의 글 뒤에 붙는다. 그대로 보내도 되고 고쳐서 보내도 된다
- 효과음은 세 가지다. 듣기 시작, 받아적기 시작("들었다"), 실패
- 처음 누를 때는 권한 창이 그 누름을 가져간다. 그래서 "마이크 준비됐어요. 다시 눌러 말하세요"를 띄운다
- 마이크는 녹음하는 동안만 연다. iOS 는 마이크를 여는 동안 다른 앱의 음악을 멈추므로, 읽어 주기가 꺼져 있으면 녹음이 끝나자마자 오디오를 놓아 음악이 돌아오게 한다
- 녹음했는데 소리가 하나도 들어오지 않았으면(iOS 가 오디오를 끊은 경우) 마이크를 다시 연결하고 "다시 눌러 말해 주세요"라고 알린다

### 사진

사진 버튼을 누르면 iOS 가 사진 찍기와 사진 보관함을 고르게 해 준다. 최대 4장, 폰에서 긴 변 1600px JPEG 로 줄인다. 보내기 전에는 입력창 위에 썸네일로 기다리고 하나씩 뺄 수 있다. 사진만 보내도 된다. 보낸 사진은 내 말풍선에서 글 위에 보인다. 사진은 모델에만 가고, memory 레포에는 커밋 메시지와 대화 정리 기록에 `[사진 N장]`만 남는다.

## 답 받기

보내는 즉시 내 말풍선과, 점 세 개가 움직이는 까치 말풍선이 생긴다. 그 뒤로 서버가 이벤트를 보낸다.

| 이벤트 | 화면 |
|---|---|
| `delta` | 답 글자를 오는 대로 Markdown 으로 그린다 (화면 갱신 한 번에 한 번) |
| `aside` | 도구를 부르기 전에 한 말("노트를 찾아볼게요")은 흐린 곁말로 남기고, 읽어 주기에서는 뺀다 |
| `activity` | 점 옆에 지금 하는 일: 노트 찾는 중, 기억하는 중, 웹에서 찾는 중, 사진 찍는 중, 다른 에이전트에게 맡기는 중 등 |
| `photo` | 도구가 가져온 사진(기기 카메라)을 답 아래 전체 폭으로 |
| `done` | 답에 쓴 노트를 제목 칩으로. 이번 턴에 고친 노트는 "기억함:" 칩으로 강조 |
| `error` | 말풍선 안에 짧은 오류 문구와 실패 효과음 |

입력창은 세 경우 모두 보이는 화면의 맨 아래에 온다. 화면 키보드가 올라오면 입력창이 키보드 바로 위에 붙는다. iOS 는 키보드가 다 올라온 뒤에야 높이를 알려 주므로, 지난번 키보드 높이를 기억해 두었다가 누르는 순간 그만큼 먼저 올린다. iPhone 이나 iPad 에 외부 키보드를 연결해 쓰면 화면 키보드는 안 나오고 iOS 가 화면 맨 아래에 작은 막대를 띄운다. 이때는 입력창을 그 막대 바로 위에 둔다. 컴퓨터에서는 아무것도 바뀌지 않는다.

대화 목록은 맨 아래를 보고 있을 때만 새 내용을 따라 내려간다. 위로 올려 이전 답을 읽는 중이면 그대로 두고, 내가 보내면 맨 아래로 간다. 끝까지 끌어도 페이지 전체가 튀지 않고, 화면 위치 보정은 키보드나 외부 키보드의 도구 막대가 화면을 가린 높이까지만 한다. 가린 것이 없으면 하지 않는다.

말 없이 도구만 쓰고 끝난 턴은 빈 말풍선을 지운다. 오류 문구는 상황마다 하나씩이다. 모델이 모두 바쁠 때 "지금 모델들이 모두 바빠요. 잠시 뒤에 다시 말해 주세요.", 노트를 동기화하지 못했을 때 "노트 저장소를 동기화하지 못했어요. 컴퓨터에서 확인이 필요해요.", 연결이 끊긴 채 돌아오지 못했을 때 "연결이 끊겼어요. 다시 보내 주세요."

### 끊겼을 때

앱은 턴마다 id 를 붙인다. 스트림이 끊기면 같은 id 로 다시 요청하면서 이미 받은 이벤트 수를 함께 보내고, 서버는 그다음부터 보낸다. 서버는 15초마다 신호를 보내고, 앱은 45초 동안 아무것도 받지 못하면 끊긴 것으로 본다. 앱이 다시 앞으로 나오면 바로 다시 연결한다. 다섯 번 연속 실패하거나, 서버가 재시작해서 그 턴을 모르면 포기하고 오류 문구를 띄운다. 어느 경우든 서버는 턴을 끝까지 돌리고 커밋한다.

## 읽어 주기

기기마다 따로 켜고 끄며, 기본은 꺼짐이다. 켜면 답의 첫 두 문장만 소리로 읽고 나머지는 화면에만 둔다. URL, 파일 경로, Markdown 기호는 읽지 않는다. 문장이 완성되는 대로 합성해서 순서대로 재생하고, 새 메시지를 보내거나 녹음을 시작하면 멈춘다. 목소리와 말 빠르기는 설정에서 고르고, 서버에 저장되어 모든 기기에 같이 적용된다.

## 말의 의도

정해진 명령어는 없다. 모든 말은 까치에게 가고, 까치가 의도를 판단해 도구를 부른다.

| 말 (예) | 까치가 하는 일 |
|---|---|
| "방금 거 취소해", "없던 걸로 해줘" | `memory_undo`: memory 서비스가 직전 커밋을 되돌리고 push 한다. 애매하면 무엇을 되돌릴지 묻는다 |
| "아니 3시 반이야" | 정정. 노트를 고친다 (되돌리지 않음) |
| "아니 기아 말고 깃허브" | 잘못 받아쓴 용어를 `vocabulary.md` 에 더한다. 다듬기를 켜 두면 다음부터 그 단계에서 바로잡는다 |
| "정리해줘" | `tidy_notes`: 이 턴이 끝난 뒤 사서가 노트를 정리한다 |
| "됐어 고마워", "잘 자" | 짧게 인사하고 `end_conversation`. 사서가 정리를 시작한다 |
| "내가 직접 할게", "컴퓨터로 이어서 할게" | 짧게 답하고 `handoff`. 사서가 정리를 시작한다 |
| "거실에서 밥 먹으라고 말해줘" | `device_speak` |
| "거실 지금 어때?" | `device_snapshot`. 사진은 답 아래에 |

웹 검색, 설정의 도구에서 붙인 MCP, 코드 작업 같은 나머지 요청은 그 도구로 바로 실행한다.

## 설정

메뉴 맨 아래의 설정 화면이다. 먼저 계정, 외형, 음성, 모델, 도구 다섯 카테고리가 지금 값과 함께 보이고, 하나를 누르면 그 설정만 있는 화면이 열린다. 화면, 글자 크기, 읽어 주기는 이 기기에만, 나머지는 서버에 저장된다.

- 계정: AI 와 서비스 두 묶음. AI 는 Claude, ChatGPT, OpenAI API, OpenRouter, 그리고 받아쓰기와 다듬기에 쓰는 Groq 키. 서비스는 Google(캘린더, Gmail, 드라이브), Notion, GitHub 로, 연결을 누르면 필요한 값만 묻고 붙인 뒤 OAuth 가 필요하면 바로 로그인 단계로 간다. 로그인은 로그인 페이지를 열고, 끝에 열리지 않는 127.0.0.1 페이지의 주소를 붙여 넣는다. AI 는 연결된 것은 "구독으로 연결됨"이나 "API 키로 연결됨"과 연결 해제 버튼, 안 된 것은 연결 버튼. 연결을 누르면 목록 아래에 단계가 열린다. Claude 구독은 로그인 페이지를 열고 받은 코드를 붙여 넣고, ChatGPT 구독은 OpenAI 페이지에 화면의 코드를 넣으면 저절로 연결된다. API 키는 입력란 하나. 서버가 폰과 다른 기기라 로그인이 서버로 바로 돌아올 수 없어서 이렇게 한다
- 외형: 화면(폰 설정대로, 밝게, 어둡게), 글자 크기(본문 크기를 정하면 다른 글자도 같은 비율로), 대화(생각 과정 보기, 도구 사용 보기. 이 폰에만, 기본은 꺼짐. 켜면 답 말풍선 안에 모델이 생각한 것과 쓴 도구, 그 결과가 차례대로 흐리게 보인다. 생각은 답이 나오기 시작하면 접힌다)
- 음성: 두 묶음이다. 목소리(까치가 말할 때)는 이 폰에서 읽어 주기 스위치(이 기기에만), 목소리 줄(누르면 만드는 곳 기기, 이 컴퓨터, 온라인과 그 목소리들을 고르는 화면. 엔진마다 마지막에 고른 목소리를 기억한다), 말 빠르기. 받아쓰기(내가 말할 때)는 받아쓰는 곳(이 컴퓨터, Groq)과 다듬기(끄기, Groq). 줄마다 말이 밖으로 나가는지 짧게 보이고, 이 컴퓨터의 서버가 꺼져 있거나 Groq 키가 없으면 빨갛게 그렇다고 말한다. `.env.local` 의 값은 처음 값일 뿐이다
- 생각 깊이: 빠르게, 보통, 꼼꼼하게
- 모델: 로그인한 provider 의 모델만, OpenRouter 는 무료 모델만. 막히면 넘어갈 모델 순서도 보인다
- 도구: 기본(기기, 노트. 끌 수 없음), 추가한 것(켜고 끄는 스위치, 삭제, 연결됐는지와 도구 수), 추가하기(추천하는 Home Assistant 와 LG ThinQ 는 필요한 값만 묻고, 직접 추가는 주소나 실행 명령). 화면에는 Pi 라는 이름을 쓰지 않는다
- 새 대화(메뉴): 대화 흐름만 비우고 기억은 그대로. 지난 대화는 메뉴에 남는다

기기에 한 말을 다루는 설정은 없다. 까치 홈 대화의 한 턴이 되고, 들은 기기가 답하고, 도구는 까치 홈과 같다([bus.md](bus.md)).

## 까치 홈 피드

앱이 열려 있는 동안 기기 대화와 `send_to_phone` 메시지가 대화 목록에 들어온다. 기기 대화는 내 말풍선 자리에 "거실에서"를 달고, 메시지는 까치 말풍선 위에 "까치가 보냈어요"를 단다. 앱을 닫았다 열면 그사이 온 것을 보여준다. 기기 대화는 그 기기가 이미 말했으니 소리로 읽지 않고, "까치가 보냈어요" 메시지만 읽어 주기가 켜져 있을 때 읽는다.

## 기기 페이지 (/device)

안 쓰는 폰이나 태블릿을 방에 두고 쓰는 페이지다. 처음 열면 이름(예: 거실)을 붙이고, "탭해서 시작"을 한 번 누른다. 이 한 번의 누름으로 소리를 켜고, 화면이 꺼지지 않게 하고, 마이크, 카메라, 동작 및 방향, 위치 권한을 한꺼번에 받는다. 나중에 권한 창이 뜨면 아무도 누르지 않아 멈추기 때문이다. 까치 홈 설정에서 허용하기 전까지는 "허용해 주세요"만 보인다.

메인 화면 정중앙에는 누르고 말하는 음성 패드가 있다. 이 기기의 음성이 까치에게 열려 있을 때만 나온다. 패드 위에는 들은 말과 답이, 아래에는 상태 한 줄과 입력 상태 줄이 있다. 가로로 두면 말은 버튼 왼쪽, 상태와 입력은 오른쪽에 온다. 입력 상태 줄에는 음성, 카메라, 소리 크기, 움직임 센서, 위치 아이콘이 나란히 있고, 닫힌 것은 흐리게, 까치가 쓰는 중인 것은 배경을 밝혀 보여준다. 오른쪽 아래 버튼은 기록을 연다. 이 기기에서 있었던 일이 시간과 함께 최근 50개까지 남는다. 방에 있는 사람도 카메라나 마이크가 언제 쓰였는지 알 수 있다. 화면은 어느 방향으로 두어도 스크롤되지 않는다. 공간이 모자라면 패드가 작아지고 들은 말과 답이 몇 줄에서 잘린다.

조명은 이 화면에서 고르지 않는다. 까치가 `device_light` 로 색과 밝기를 정해 켜면 화면 전체가 그 색이 되고, 켜져 있는 동안에는 패드도 사라진다. 말하는 도중에 켜지면 그때까지 한 말을 보낸다. 화면을 누르면 꺼지고 패드가 돌아온다. 조명은 태블릿만 된다.

오른쪽 위 버튼이나 입력 상태 줄을 누르면 "이 기기" 시트가 열린다. 출력(스피커, 조명)과 입력(음성, 카메라, 소리 크기, 움직임 센서, 위치)이 카드로 있고 지금 상태만 보여 준다. 여기에는 스위치가 없다. 까치가 무엇을 쓸지는 까치 홈의 기기에서 정한다. 닫아 둔 것은 서비스가 거절하고 까치도 그렇게 답한다.

음성 패드를 누르고 있는 동안 말하고 떼면 보낸다. 보낸 말은 까치가 받았다고 알려줄 때까지 기기에 남아 다시 보내지고, 60초가 지나면 버려진다. 힌트는 "보내는 중…", "전했어요" 순으로 바뀐다. 기기는 답을 기다리지 않고 바로 다음 말을 받을 수 있다. 답은 이 기기에서 소리로 나오고 들은 말과 답이 화면에 남는다. 까치 홈 대화의 한 턴이라 도구도 까치 홈과 같다([bus.md](bus.md)). 페이지가 예전 버전이면 새로고침 버튼 하나를 띄운다.

## 음성 처리

```
마이크 → 16kHz WAV → /api/stt → 받아쓰기 (Groq whisper-large-v3) → (켜 두면) 다듬기 (Groq gpt-oss-120b) → 입력창
보내기 → /api/turn (SSE) → Pi → 완성된 문장 → 폰의 내장 목소리 (또는 /api/tts 의 서버 목소리) → 재생
```

- 받아쓰기: 모든 구간의 무음 확률이 0.4를 넘으면 버린다. "시청해주셔서 감사합니다"처럼 Whisper 가 무음에서 지어내는 문구만 있으면 그것도 버린다. Whisper 의 `prompt`(용어 힌트)는 쓰지 않는다. 무음에서 힌트를 그대로 받아적었다
- 다듬기: 기본은 꺼져 있다. 받아쓸 때마다 외부 LLM 을 한 번 더 부르는 일이라서다([philosophy.md](philosophy.md) 2번). 꺼져 있어도 "아 아 아" 같은 소리와 Whisper 가 무음에서 지어낸 문구는 규칙으로 버리고, 나머지는 들은 그대로 입력창에 둔다. `KKACHI_POLISH_MODEL` (예: Groq 의 `openai/gpt-oss-120b`)을 정하면 켜진다. 켜면 용어 목록(`vocabulary.md`, 노트 제목, 기본 용어)으로 잘못 들은 영어 용어와 숫자를 고친다. "아 아 아"처럼 말이 아닌 소리는 버린다. 2.5초 안에 끝나지 않으면 원문을 그대로 쓴다. 다듬은 문장이 원문과 다르면 까치에게 원문도 함께 보낸다
- 읽어 주기: 기본은 "기기 목소리", 폰과 기기에 들어 있는 목소리(Web Speech API)다. 문장이 서버로 가지 않고, 기기 안에서 만드는 한국어 목소리를 먼저 고른다. iOS 는 처음 한 번을 탭 안에서 말해야 해서 보내기 탭(기기는 "탭해서 시작")에서 소리 없는 한 마디를 말해 둔다. 설정에서 Edge TTS 목소리를 고르면 서버가 만든다. Edge 는 가끔 소리 없이 응답해서 한 번 더 시도한다
- 이 컴퓨터에서 만드는 목소리(선택): [Supertonic 3](https://huggingface.co/Supertone/supertonic-3)(ONNX, CPU, 99M, 한국어 포함 31개 언어). `uv run scripts/supertonic-server.py` 로 띄우고 `.env.local` 에 `KKACHI_TTS_PROVIDER=supertonic` 을 넣으면 설정의 목소리 목록이 Edge 대신 여성 1~5, 남성 1~5가 된다. 문장이 집 밖으로 나가지 않는다. 노트북 CPU(i5-10210U)에서 5초짜리 문장이 1.5초에 만들어진다(3단계. `SUPERTONIC_STEPS` 를 올리면 더 좋고 더 느리다: 2단계 1.3초, 5단계 2.2초, 8단계 3.5초). 알려진 문제: 숫자를 가끔 틀리게 읽는다("영하 2도"를 "영하 두 도"). 원 저장소는 보관 처리되어 더 고쳐지지 않고, 모델 라이선스는 OpenRAIL-M 이다
- 원본 녹음은 저장하지 않는다

받아쓰기와 TTS 는 OpenAI 호환 API 하나로 다뤄서, 클라우드와 로컬을 같은 코드로 쓴다.

| | 인터페이스 | 클라우드 예 | 로컬 예 |
|---|---|---|---|
| 받아쓰기 | `POST /v1/audio/transcriptions` | Groq Whisper, OpenAI | whisper.cpp 의 `whisper-server` (아래), OpenAI 호환 서버로 띄운 Qwen3-ASR 또는 faster-whisper |
| TTS | `POST /v1/audio/speech` | OpenAI TTS | 기본값인 기기 목소리가 이미 로컬. 서버 목소리는 Supertonic 3 (`scripts/supertonic-server.py`) |

설정은 provider 마다 `BASE_URL`, `API_KEY`, `MODEL` (TTS 는 `VOICE` 추가)이다.

### 로컬 받아쓰기 (선택)

whisper.cpp 의 `whisper-server` 는 까치가 보내는 요청을 그대로 받는다. `verbose_json` 에 무음 확률(`no_speech_prob`)도 담겨 잡음 거르기가 같이 동작한다. 코드는 그대로이고 설정만 바꾼다.

1. [whisper.cpp 릴리스](https://github.com/ggml-org/whisper.cpp/releases)에서 실행 파일(Windows 는 `whisper-bin-x64.zip`)을, [Hugging Face](https://huggingface.co/ggerganov/whisper.cpp)에서 모델(`ggml-small.bin`, 466MB)을 받는다.
2. `whisper-server -m ggml-small.bin -l ko -t 8 --port 8091 --inference-path /v1/audio/transcriptions` 로 띄운다. Git Bash 에서는 경로가 Windows 경로로 바뀌지 않게 앞에 `MSYS_NO_PATHCONV=1` 을 붙인다.
3. `.env.local` 에 `KKACHI_STT_BASE_URL=http://127.0.0.1:8091/v1`, `KKACHI_STT_MODEL=whisper-small` 을 넣는다. 모델 이름에 `whisper` 가 들어가야 무음 확률을 요청한다.

GPU 없는 노트북(i5-10210U, 8스레드)에서 잰 값이다. 모델을 올려 둔 뒤 짧은 문장(약 6초) 기준이다.

| 모델 | 짧은 문장 | 14초 문장 | 한국어 |
|---|---|---|---|
| Groq `whisper-large-v3` (기본, 외부) | 0.4초 | 0.5초 | 정확 |
| `base` | 2.9초 | 4.1초 | 뜻이 바뀌는 오류 ("예약해 두고" → "이야기해두고") |
| `small` | 10초 | 14초 | 정확 |
| `small-q5_1` | 11.5초 | 15초 | 정확, 더 빠르지 않음 |
| `large-v3-turbo-q5_0` | | 15초 넘게 인코딩에만 | 반복해서 말을 지어냄 |

작은 GPU 가 있으면 [speech.cpp](https://github.com/nyosegawa/speech.cpp) 의 Qwen3-ASR 0.6B 가 더 빠르다. `speech serve qwen3-asr-0.6b silero-vad --port 8091` 로 띄우고 `KKACHI_STT_BASE_URL=http://127.0.0.1:8091/v1`, `KKACHI_STT_MODEL=Qwen3-ASR-0.6B`, `KKACHI_STT_CHUNKING=auto`, `KKACHI_STT_API_KEY=` 를 넣는다. GeForce MX250(2GB)에서 3초 문장이 0.4초, 10초 문장이 1.7초였다(합성 음성으로 잰다). 이 모델은 무음 확률을 주지 않고 무음에서 말을 지어내서(무음 3초에 "이미."), `KKACHI_STT_CHUNKING=auto` 로 서버의 음성 감지(Silero VAD)가 찾은 구간만 받아쓰게 한다. CPU 만으로는 3초 문장에 2.7초, 10초 문장에 9초가 걸렸다. 같은 프로그램의 Qwen3-TTS 0.6B 는 이 GPU 에서 말하는 속도를 겨우 따라가거나 못 따라가서 쓰지 않는다.

인코더는 말 길이와 상관없이 30초 분량을 처리해서 짧은 말도 느리다. `-ac 512` 로 줄이면 `small` 이 3.6초까지 빨라지지만 10초를 넘는 말은 뒷부분을 잘못 쓴다. 그래서 GPU 없는 노트북에서는 Groq 가 기본이고, 로컬은 기다릴 수 있을 때 고르는 선택이다. iPhone 에서는 키보드의 받아쓰기 버튼도 있다. 입력창에 글로 들어가고, 까치 서버를 거치지 않는다.

## iOS 제약

- 앱이 백그라운드로 가거나 화면이 꺼지면 마이크가 끊긴다. 그때까지 녹음한 말은 받아적는다
- 첫 소리와 첫 마이크에는 탭이 필요하다
- Safari 내장 `webkitSpeechRecognition` 은 쓰지 않는다. iOS 27 에서 탭당 한 번만 동작하는 회귀가 있고, 재생 뒤 다시 시작하면 깨진다
- 홈 화면에 추가해 standalone 으로 연다. HTML 과 JS 는 `Cache-Control: no-cache` 로 내보내 업데이트가 새로고침으로 바로 반영된다
- 기기는 화면을 켜 둬야 한다. Wake Lock 은 iOS 16.4부터 되고, 홈 화면 앱에서는 18.4 전까지 버그가 있다

| 구간 | 목표 | 측정 |
|---|---|---|
| 받아쓰기 + 다듬기 | 1초 안팎 | 0.4초 + 0.5~0.8초 |

| 문장 읽기 (Edge TTS) | 1초 | 보통 2초 안팎, 기기 측정에서는 2~30초로 들쭉날쭉 |

## 상태

컨트롤마다 기본, hover(포인터 기기만), focus(키보드, 3px 청록 링이 바로), active(누르는 동안), disabled, 진행 중, 오류 상태를 갖춘다. disabled 는 흐림 하나로 표시하지 않는다. 보내기 버튼은 회색 바탕에 흐린 화살표와 금지 커서, 서버를 기다리는 버튼은 흐린 글자와 진행 커서, 기기의 쓸 수 없는 카드는 바탕 없이 테두리만 남는다. 상태 문구는 가운뎃점으로 잇지 않고 문장으로 쓴다("듣고 있어요. 다시 누르면 받아적어요", "오후 3:02에 까치가 …").
