# 웹앱 디자인 — 음성 전용

Kkachi 는 **음성만으로 쓰는 앱**이다. 화면은 상태를 보여주는 보조 수단이고, 키보드 입력은 없다. 화면 탭은 대화 시작과 끼어들기 두 가지에만 쓴다.

## 원칙

1. **한 번 탭하면 그다음은 말로만** — 대화가 시작되면 듣기 → 생각 → 말하기 → 다시 듣기를 손 없이 반복한다
2. **귀로 듣는 답** — 기본은 한 문장, 가장 중요한 사실 하나. 소리로는 최대 두 문장만 읽고 나머지는 화면에만. 표·목록·경로는 말하지 않는다
3. **새 말이 우선** — 답을 준비하는 중에 다시 말하면 앞의 턴을 중단하고 새 말을 처리한다 ("아직 처리 중" 거절 없음)
3. **기다리는 동안 조용하지 않게** — 말이 끝나면 바로 짧은 효과음으로 "들었다"를 알린다. 기다리는 동안 "찾아볼게요" 같은 상투적인 말은 하지 않는다 (어색해서 뺀). 화면 상태로만 보여줌
4. **기억은 조용히** — "노트에 적었어요" 같은 말을 하지 않는다. 사람이 기억하듯 내용에만 반응하고("토요일 3시 반 치과요, 알겠어요"), 기억할 만한 말은 요청이 없어도 레포에 반영한다. 잡담은 저장하지 않음
5. **명령어가 아니라 대화** — 정해진 문구가 없다. 끝내기·되돌리기·정정·다시 말하기를 까치(LLM)가 말의 의도로 판단한다
6. **틀리면 말로 되돌린다** — 기록은 바로 반영하고, "방금 거 취소해" 로 되돌리거나 "아니 3시 반이야" 로 고친다

## 상태

```
        탭                    말 끝 (VAD)
 대기 ─────▶ 듣기 ──────────────────────▶ 인식 ──▶ 생각 ──▶ 말하기 ─┐
  ▲           ▲                                                      │
  │           └──────────────── 말하기 끝 (자동) ◀───────────────────┘
  │
  └── 까치가 대화 끝을 판단 / 탭 (듣기 중)      탭 (말하기 중) ──▶ 말 끊고 듣기

침묵으로는 끝나지 않는다. 화면이 켜져 있는 동안 계속 듣는다.
```

| 상태 | 화면 | 소리 |
|---|---|---|
| 대기 | 어두운 화면, 가운데 까치 아이콘. "탭해서 시작" | 없음 |
| 듣기 | 아이콘이 목소리 크기에 따라 커짐. 인식 중인 말은 표시하지 않음 | 시작 효과음 |
| 인식·생각 | 아이콘이 천천히 숨 쉬듯 움직임. 내가 한 말(인식 결과)을 크게 표시 | 말이 끝나면 "들었음" 효과음. 노트 작업이 시작되면 짧은 말(미리 합성해 둔 음성). 7초가 넘으면 "조금만 기다려 주세요" |
| 말하기 | 답 텍스트를 크게 표시. 아래에 출처 노트 칩, 수정이 있으면 "노트 수정됨" 칩 | 답 음성 |
| 오류 | 짧은 오류 문구 ("모델이 바빠요. 다시 말해 주세요") | 오류 효과음 + 같은 내용을 음성으로 |

## 화면

```
┌─────────────────────────┐
│                         │
│   "제주 숙소 어디였지?"   │  ← 내가 한 말 (작게, 흐리게)
│                         │
│          ◉              │  ← 상태 아이콘 (화면 중앙, 크게)
│                         │
│  서귀포 바다호텔로        │  ← 답 (크게)
│  확정했어요.             │
│                         │
│  📄 projects/jeju-trip   │  ← 출처 칩
└─────────────────────────┘
```

- 전체 화면 하나. 설정·메뉴 버튼 없음. 다크 배경 (침대 옆에서 써도 눈부시지 않게)
- 직전 한 턴만 보여준다. 길게 누르면 오늘 대화 기록(텍스트)을 연다
- 출처 칩은 agent 가 실제로 읽거나 고친 파일(tool 호출 기록)에서 만든다. 모델이 쓴 "Sources:" 문구에 의존하지 않음
- 홈 화면에 추가(PWA)해 standalone 으로 연다

## 음성 파이프라인

```
마이크 (getUserMedia, echoCancellation)
  → VAD (브라우저, 소음 기준선을 재는 에너지 VAD. 실기기에서 충분했음. 오인식이 많으면 Silero VAD wasm 으로 교체) 로 말 구간만 잘라냄
  → POST /api/stt (오디오) → 웹앱 서버 → STT provider → 텍스트 → 작은 LLM 으로 다듬기 (오인식·숫자 교정, ~0.6초)
  → Pi prompt → 최종 답 텍스트 (도구 사이 중계는 버림)
  → 문장 단위로 잘라 TTS provider 로 → 오디오를 순서대로 재생
  → 마지막 문장 재생이 끝나면 다시 듣기
```

- 마이크 스트림은 대화 중 계속 열어 두고, 말하기 동안에는 VAD 만 멈춘다 (자기 목소리를 듣지 않도록). 스트림을 껐다 켜면 iOS 에서 권한·지연 문제가 생김
- 소리 재생은 첫 탭 때 만든 AudioContext 하나로 한다 (iOS 는 첫 재생에 탭이 필요)
- Safari 내장 `webkitSpeechRecognition` 은 쓰지 않는다. iOS 27 에서 탭당 한 번만 동작하는 회귀가 있고, 재생 후 재시작이 깨짐
- 원본 녹음은 저장하지 않는다. STT 후 바로 버림
- 대화 중에는 Screen Wake Lock 으로 화면이 꺼지지 않게 한다 (화면이 꺼지면 마이크가 끊김). 대기 상태로 가면 해제

### STT·TTS provider

둘 다 OpenAI 호환 API 하나로 다룬다. 클라우드와 로컬을 같은 코드로 지원하기 위함.

| | 인터페이스 | 클라우드 예 | 로컬 예 |
|---|---|---|---|
| STT | `POST /v1/audio/transcriptions` | Groq Whisper, OpenAI | OpenAI 호환 서버로 띄운 Qwen3-ASR 또는 faster-whisper (M1 에서 후보 확인) |
| TTS | `POST /v1/audio/speech` | OpenAI TTS | 첫 버전은 클라우드만 |

설정은 provider 마다 `BASE_URL`, `API_KEY`, `MODEL` (TTS 는 `VOICE` 추가).

## 답변 말투

agent system prompt 에 추가할 규칙:

- 말로 읽힐 답이다. 1~3문장, 마크다운·목록·파일 경로 없이
- 기록했으면 무엇을 어디에 적었는지 한 문장으로 ("제주 여행 노트에 숙소를 서귀포 바다호텔로 적었어요")
- 노트에 없으면 "노트에는 없어요" 라고 짧게
- 음성 인식 오류가 있을 수 있다. 뜻이 애매한 고유명사·숫자는 기록 전에 한 번 되묻는다

## 대화 의도 (명령어 없음)

정해진 음성 명령은 두지 않는다. 모든 말은 까치에게 가고, 까치가 의도를 판단해 필요하면 앱이 주는 도구를 부른다.

| 말 | 동작 |
|---|---|
| 말의 의도 (예) | 까치가 하는 일 |
|---|---|
| "방금 거 취소해", "없던 걸로 해줘" | `undo_last_change` → 직전 Kkachi 커밋을 `git revert`, 턴 끝에 push. 애매하면 무엇을 되돌릴지 되물음 |
| "아니 3시 반이야" | 정정. 노트를 고침 (되돌리지 않음) |
| "됐어 고마워", "잘 자" | 짧게 인사하고 `end_conversation` → 앱이 대기 상태로 |
| "내가 직접 할게", "컴퓨터로 이어서 할게", "잠깐 딴 사람이랑 얘기 좀" | handoff. 짧게 답하고 `handoff` → 듣기를 끔 |
| "다시 말해줘", "뭐라고?" | 직전 답을 다시 말함 |
| TV·다른 사람 말 | 자기에게 한 말이 아니면 답하지 않음 |

도구는 까치 전용 Pi 확장 `pi/kkachi.ts`. 앱은 Pi 이벤트에서 `end_conversation`·`handoff` 호출을 보고 듣기를 멈춘다. 그 밖의 요청(웹 검색, 브라우저·캨린더 MCP, 코드 작업)은 사용자의 Pi 설정에 있는 도구로 바로 실행한다.

## 지연 목표

말이 끝난 뒤:

| 시점 | 목표 |
|---|---|
| "들었음" 효과음 | 즉시 (VAD 종료 시점) |
| 인식 결과 표시 | 1초 이내 |
| 답 첫 음성 | 질문 4초, 기록 8초 이내. M1 측정(맥, LLM 만): 질문 2.8~4.0초, 기록 7.7초. 실기기는 여기에 STT ~0.8초 + TTS ~1초 (M0 에서 LLM 턴 5~11초 → 첫 문장 스트리밍으로 단축) |

## iOS 제약

- 화면이 꺼지거나 앱이 백그라운드로 가면 마이크가 끊긴다. 화면을 켠 채로 쓴다 (전용 공기계는 자동 잠금 끄기)
- 첫 마이크·소리에는 탭이 필요하다. 그래서 "한 번 탭 후 핸즈프리"
- 실제 기기 동작(standalone PWA 마이크, 재생 후 VAD 재개, 에코)은 M1 첫 작업으로 확인한다

## 나중에

- 호출어 "까치야" (화면이 켜진 동안 대기 상태에서 듣기)
- 말로 끼어들기 (말하는 중에 사용자가 말하면 멈춤. 에코 처리 필요)
- 로컬 TTS
