# 입력 버스

공기계에서 들어온 입력을 core 가 받아 처리하고, 출력을 어디로 보낼지 정하는 방식. 구조 전체는 [modules.md](modules.md), 공기계 기능은 [sensors.md](sensors.md), 화면 동작은 [design.md](design.md).

## 모델

입력은 사건이고 출력은 명령이다. 두 흐름은 서로를 모른다.

```
입력 기기 ──(사건)──▶ kkachi-devices ──▶ core 버스: 접수 → 세션 고르기 → 에이전트 → 출력 고르기
                                                                            │
출력 기기, 까치 홈 ◀──(명령)───────────────────────────────────────────────────┘
```

- 기기는 사건을 내보내고 끝낸다. 답을 기다리지 않는다. 같은 공기계가 입력도 하고 출력도 하지만, 그 기기가 답을 받는 건 라우팅 규칙이 그렇게 정했을 때뿐이다
- ACK 는 전송 확인이다. "core 가 사건을 받았다"는 뜻이고, 결과와는 상관이 없다
- 출력은 core 가 정한 대상에게 단방향으로 간다. 말하기처럼 완료를 알려주는 출력도 다시 보내지는 않는다. 같은 말을 두 번 하는 것보다 한 번 놓치는 쪽이 낫다

에이전트가 부르는 당겨오는 입력(사진, 소리 크기, 센서)은 지금처럼 요청과 응답을 id 로 짝 맞춘다. 이 문서는 기기가 먼저 시작하는 밀려오는 입력을 다룬다. 지금은 말 걸기 하나이고, 나중에 움직임 감지와 호출어가 같은 길로 들어온다.

## 전송

```
기기                        kkachi-devices                       core
input {id, kind, at, 오디오} ─▶ 토큰·스위치 확인, id 중복 제거 ─▶ POST /api/bus/input
ack {id, ok}               ◀─────────────────────────────────── 접수 (만료면 거절)
                                                               받아쓰기 → 세션 → 에이전트
reply {inputId, heard, 답}  ◀── device_reply (core 전용 도구) ◀── 답을 이 기기로 보낼 때
```

- id 는 기기가 만든다(UUID). devices 서비스와 core 가 둘 다 최근 id 를 기억해서, 같은 사건은 한 번만 처리한다
- 기기는 ACK 를 받을 때까지 사건을 대기열에 두고, 5초마다 그리고 다시 연결될 때 같은 id 로 다시 보낸다
- 유효시간은 말한 시각(`at`)에서 60초다. 그보다 늦게 도착한 사건은 버린다. 10분 늦게 도착한 "불 꺼줘"가 그때 실행되면 안 된다
- ACK 는 core 가 접수했을 때 보낸다. core 가 꺼져 있으면 ACK 가 없고, 기기가 유효시간 안에서 계속 다시 보낸다. 대기열은 기기에만 있고 devices 서비스는 상태를 갖지 않는다
- 답이 이 기기로 오면 `reply` 로 들은 말과 답(글, 음성)이 함께 온다. 답은 다 쓴 뒤에 한 번에 오지 않고, 에이전트가 문장을 끝낼 때마다 한 문장씩 온다(`part` 0, 1, … 그리고 `last`). 문장마다 목소리를 따로, 나란히 만들기 때문에 기기는 번호 순서로 말한다. 도구를 부르기 전에 한 말("찾아볼게요")도 말해서 기다리는 동안 조용하지 않게 하고, 끝나면 화면에는 답만 남긴다. 서버 목소리(Edge TTS)가 한 문장에 6초 넘게 걸리면 그 문장은 기기 목소리로 말한다. 전에는 답 전체를 기다렸다가 전체를 한 번에 소리로 만들어서 10~30초가 걸렸다. 답이 다른 곳으로 갔으면 들은 말과 "답은 폰에서 볼 수 있어요"만 온다. 기기가 잠깐 끊겼다 돌아오면 2분 안의 답은 다시 보낸다
- 버튼을 누르는 순간의 `warm` 은 힌트다. 처리할 세션의 Pi 를 미리 띄우고, ACK 는 없다

## 옵션

까치 홈 설정의 "공기계 대화"에서 바꾼다. 기본값은 개인 설정이라 프라이버시가 보장된다는 가정으로 정했다.

| 옵션 | 값 | 기본 |
|---|---|---|
| 대화 (`deviceSession`) | 폰과 함께: 까치 홈 대화와 한 세션 / 공기계끼리: 공기계들이 한 세션 / 기기마다: 기기별 세션 | 폰과 함께 |
| 답하는 곳 (`deviceReply`) | 들은 기기 / 폰 / 둘 다 | 들은 기기 |
| 개인적인 내용 (`devicePrivacy`) | 그대로 말하기 / 소리로 말하지 않기 / 폰으로 보내기 | 그대로 말하기 |
| 도구 (`deviceTools`) | 전체: 까치 홈 대화와 같음 / 노트·말하기·조명만 | 전체 |
| 내 MCP (`deviceMcp`) | 까치 홈만 / 공기계도 | 까치 홈만 |
| 새 대화 (`deviceIdleMin`) | 5분, 10분, 30분 조용하면 / 끄기 | 10분 |

- "폰과 함께"면 공기계에서 한 말이 까치 홈 대화의 한 턴이 된다. 까치 홈 대화는 지금처럼 이어지므로 "새 대화"는 적용되지 않고, 도구도 항상 전체다
- "공기계끼리"와 "기기마다"는 별도 세션이다. 정한 시간 동안 조용하면 다음 말부터 새 대화로 시작한다
- 까치 홈 대화에 들어간 공기계 턴과 폰으로 온 답은 까치 홈 화면에 "거실에서"처럼 출처를 달고 보인다
- 개인적인 내용의 판단은 에이전트가 한다. 턴 앞에 붙는 표시(`[기기: 거실, 개인 정보: 폰으로]`)를 보고 따른다. "폰으로 보내기"는 `send_to_phone` 도구로 까치 홈에 보낸다
- 도구가 "전체"면 공기계에 말하는 누구나 명령을 실행시킬 수 있다. 집 안 기기를 혼자 쓴다는 가정이다. 손님이 오거나 TV 소리가 걱정되면 "노트·말하기·조명만"으로 바꾼다
- "내 MCP" 는 사용자가 Pi 에 붙인 MCP 서버다(pi-mcp-adapter, Claude Code 등에서 가져온 것 포함). 메일, 저장소, 브라우저처럼 멀리 닿는 것이 많아서 기본은 까치 홈에서만 쓴다. 까치 확장이 턴마다 머리말을 보고 공기계 턴에서는 그 도구들을 끄고 까치 홈 턴에서 다시 켠다. "폰과 함께" 세션에서도 마찬가지다. `kkachi.mcp.json` 에 넣은 서버(기기, 기억, HA)는 까치 자신의 도구라 이 설정과 상관없이 "도구" 설정을 따른다

## 세션과 커밋

- 까치 홈 턴은 지금처럼 새 메시지가 앞 턴을 멈춘다. 공기계 턴은 멈추지 않고 차례를 기다린다
- 도구가 "전체"인 공기계 턴은 까치 홈 턴과 같은 줄에 서고, 끝나면 core 가 턴 하나를 커밋 하나로 만든다. 같은 레포를 동시에 고치지 않기 위해서다
- 도구가 "노트·말하기·조명만"이면 노트는 `memory_*` 도구로만 바뀌고 바꿀 때마다 커밋된다. 까치 홈 턴을 기다리지 않는다
- 모든 공기계 턴은 30분 대화 정리에 `[거실] …`로 들어간다

## 연결과 에이전트의 자원

기기의 입력이 가는 길은 두 가지이고, 서로 독립이다. 한 입력이 여러 출력과 에이전트에 동시에 갈 수 있다.

```
                      ┌─ 연결 (직접) ──────────────▶ 다른 기기의 출력   여러 개 가능, 에이전트 없음
기기의 입력 ────────────┤
                      └─ 에이전트에게 열려 있으면 ──▶ 까치 ──▶ 까치에게 열린 출력과 센서
```

- **연결**은 입력 하나와 출력 하나를 잇는 선이다. 까치 홈의 연결 탭에서 만들고, core 의 라우터(`src/router.ts`, `data/routes.json`)가 갖는다
- 까치 홈에서는 세 관계가 이렇게 나뉘어 보인다. 입력 → 출력과 입력 → 에이전트는 연결 탭의 한 줄씩이다(에이전트로 가는 입력은 음성뿐이고, 새 기기는 이미 이어져 있다). 에이전트 → 출력은 에이전트 탭의 자원에서 기기별 스피커와 조명을 켜고 끈다. 화면에서는 "까치" 대신 "에이전트"라고 쓴다
- 버튼과 다이얼은 에이전트로 가지 않는다. 출력에만 잇는다
- 연결을 지나가는 것은 일어나는 대로 까치 홈에 전해진다(`GET /api/flow`, server-sent events, `src/flow.ts`). 값이나 녹음이 출력으로 떠날 때, 음성이 에이전트로 갈 때 한 건씩이고, 전달하지 못하면 한 건 더 온다. 연결 탭은 그 줄의 화살표에 점을 한 번 흐르게 하고 아래 문구를 바꾼다. 화면을 나중에 열면 연결마다 마지막 건이 먼저 온다(메모리에만 있다)
- 조명은 태블릿만 된다. 조명이 켜지면 화면 전체를 덮어서, 조작용으로 쓰는 휴대폰에서는 패드의 터치를 가렸다
- **자원**은 에이전트에게 열어 준 입력과 출력이다(저장은 센서까지 포함해 기능별로 하지만, 화면에서 고를 수 있는 것은 음성과 스피커, 조명이고 카메라 같은 센서는 열린 채다). 고르는 곳은 여기 하나다(공기계 화면에는 스위치가 없다). kkachi-devices 가 기기마다 갖고(`data/devices.json`, `POST /api/device/<id>/agent {cap, open}`), 새 기기는 모두 열려 있다
  - 열린 음성은 에이전트의 한 턴이 된다. devices 가 core 로 넘길 때 `agent: true|false` 를 함께 보낸다
  - 열린 센서와 출력(카메라, 소리 크기, 가속도 센서, 위치, 스피커, 조명)은 에이전트가 도구로 쓴다. 닫힌 것을 에이전트가 쓰려 하면 devices 가 거절하고, `list_devices` 에도 닫혀 있다고 나온다. 연결은 에이전트가 아니라서, 까치에게 닫힌 조명이나 스피커에도 이을 수 있다
- 공기계 화면의 패드(음성, 버튼, 다이얼)는 그 입력이 갈 곳이 있을 때만 나온다. 까치에게 열려 있거나 어떤 출력에 이어져 있을 때다. core 가 연결이 바뀔 때마다 어느 입력이 이어져 있는지 devices 에 알리고(core 전용 도구 `device_links`), devices 가 기기에 `use {pads, agent}` 를 보낸다

- **워키토키**: 한 기기의 음성을 다른 기기의 스피커에 이으면, 누르고 말한 녹음이 그대로 그 기기에서 재생된다. 이 길에서는 받아쓰지 않는다. 그 기기의 음성이 까치에게도 열려 있으면 같은 말이 에이전트에게도 가고(이때는 까치의 답이 돌아온다), 닫혀 있으면 말한 기기에 "전했어요"(받는 기기가 모두 꺼져 있으면 "전하지 못했어요")만 보인다. 한 음성을 여러 스피커에 이을 수 있다. 한 방향이라 서로 주고받으려면 반대 방향 연결도 만든다. 표의 한 줄은 `{from: {device, kind: "talk"}, to: {device, output: "speak"}}` 다(core 전용 도구 `device_play`)
- **출력으로 바로**: 에이전트가 해석할 것이 없는 입력이다. 지금은 두 가지다. 공기계의 다이얼(0~100) 값이 다른 공기계의 조명 밝기가 되고, 공기계의 버튼을 누르면 조명이 켜지거나 꺼진다.

공기계 화면 가운데에는 손으로 조작하는 입력이 정사각형 패드로 놓인다. 음성, 버튼, 다이얼 중 갈 곳이 있는 것마다 하나씩이고, 두 열로 놓인다(새 기기는 음성만). 그래서 공기계 한 대가 마이크이면서 돌리는 노브이고 누르는 스위치일 수 있다.

```
기기                      kkachi-devices            core 라우터                kkachi-devices      기기
value {kind: dial, 값} ─▶ 스위치 확인 ─▶ POST /api/bus/value ─▶ 연결 표 ─▶ device_dim (core 전용) ─▶ dim {밝기}
value {kind: click}    ─▶ 같은 길                                                             ─▶ dim {toggle}
```

- 연결은 core 의 `data/routes.json` 에 있는 표다(`src/router.ts`). 까치 홈의 연결 탭에서 잇고, 켜고 끄고, 지운다. `GET /api/routes`, `POST /api/routes`, `POST /api/routes/<id>/on|off|remove`. 꺼 둔 연결은 표에 남지만 값을 보내지 않는다
- 표에 없는 입력의 값은 버린다. 한 입력을 여러 출력에 이을 수 있다. 표의 한 줄은 `{from: {device, kind}, to: {device, output}}` 다(다이얼과 버튼은 `light`, 음성은 `speak`)
- 말 걸기와 달리 ACK 도 재전송도 없다. 다이얼은 최신 값만 의미가 있어서, 기기는 1초에 최대 10번 보내고 라우터는 한 출력으로 값이 가는 동안 뒤에 온 값 중 마지막 것만 이어서 보낸다. 버튼은 누른 횟수가 의미라서 하나도 빼지 않고 순서대로 보낸다
- 출력 기기가 꺼져 있으면 그 값은 버리고, 연결 탭의 그 카드에 "전달하지 못했어요"가 보인다
- 밝기 0은 조명을 끈다. 버튼으로 켤 때와 다이얼로 켤 때 모두 그 조명이 마지막에 띠던 색을 쓰고, 버튼은 마지막 밝기로 켠다
- 에이전트가 말로 연결을 만들거나 고치는 도구는 아직 없다

## 까치 홈 피드

까치 홈은 열려 있는 동안 `/api/feed` 를 듣는다. 공기계 턴(폰과 함께이거나, 답하는 곳에 폰이 들어갈 때)과 `send_to_phone` 메시지가 온다. 마지막으로 본 번호를 기억해 두었다가 다시 열 때 그 뒤의 것만 받는다. 피드는 서버 메모리에 최근 100개만 두고, 서버가 재시작하면 비워진다. 답하는 곳에 폰이 들어간 항목은 폰의 읽어 주기가 켜져 있으면 소리로도 읽는다.
