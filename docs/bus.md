# 입력 버스

공기계에서 들어온 입력을 core 가 받아 처리하고, 출력을 어디로 보낼지 정하는 방식. 구조 전체는 [plan.md](plan.md), 공기계 기능은 [sensors.md](sensors.md), 화면 동작은 [design.md](design.md).

## 모델

입력은 사건이고 출력은 명령이다. 두 흐름은 서로를 모른다.

```
입력 기기 ──(사건)──▶ kkachi-devices ──▶ core 버스: 접수 → 세션 고르기 → 에이전트 → 출력 고르기
                                                                            │
출력 기기, 폰 앱 ◀──(명령)─────────────────────────────────────────────────────┘
```

- 기기는 사건을 내보내고 끝낸다. 답을 기다리지 않는다. 같은 공기계가 입력도 하고 출력도 하지만, 그 기기가 답을 받는 건 라우팅 규칙이 그렇게 정했을 때뿐이다
- ACK 는 전송 확인이다. "core 가 사건을 받았다"는 뜻이고, 결과와는 상관이 없다
- 출력은 core 가 정한 대상에게 단방향으로 간다. 말하기처럼 완료를 알려주는 출력도 다시 보내지는 않는다. 같은 말을 두 번 하는 것보다 한 번 놓치는 쪽이 낫다

에이전트가 부르는 당겨오는 입력(사진, 소리 크기, 센서)은 지금처럼 요청과 응답을 id 로 짝 맞춘다. 이 문서는 기기가 먼저 시작하는 밀려오는 입력을 다룬다. 지금은 말 걸기 하나이고, 나중에 움직임 감지와 호출어가 같은 길로 들어온다.

## 전송

```
기기                        kkachi-devices                       core
input {id, kind, at, 오디오} ─▶ 토큰·스위치 확인, id 중복 제거 ─▶ POST /api/bus/input
ack {id, ok}               ◀─────────────────────────────────── 접수 (만료면 거절)
                                                               받아쓰기 → 세션 → 에이전트
reply {inputId, heard, 답}  ◀── device_reply (core 전용 도구) ◀── 답을 이 기기로 보낼 때
```

- id 는 기기가 만든다(UUID). devices 서비스와 core 가 둘 다 최근 id 를 기억해서, 같은 사건은 한 번만 처리한다
- 기기는 ACK 를 받을 때까지 사건을 대기열에 두고, 5초마다 그리고 다시 연결될 때 같은 id 로 다시 보낸다
- 유효시간은 말한 시각(`at`)에서 60초다. 그보다 늦게 도착한 사건은 버린다. 10분 늦게 도착한 "불 꺼줘"가 그때 실행되면 안 된다
- ACK 는 core 가 접수했을 때 보낸다. core 가 꺼져 있으면 ACK 가 없고, 기기가 유효시간 안에서 계속 다시 보낸다. 대기열은 기기에만 있고 devices 서비스는 상태를 갖지 않는다
- 답이 이 기기로 오면 `reply` 로 들은 말과 답(글, 음성)이 함께 온다. 답이 다른 곳으로 갔으면 들은 말과 "답은 폰에서 볼 수 있어요"만 온다. 기기가 잠깐 끊겼다 돌아오면 2분 안의 답은 다시 보낸다
- 버튼을 누르는 순간의 `warm` 은 힌트다. 처리할 세션의 Pi 를 미리 띄우고, ACK 는 없다

## 옵션

폰 앱 설정의 "공기계 대화"에서 바꾼다. 기본값은 개인 설정이라 프라이버시가 보장된다는 가정으로 정했다.

| 옵션 | 값 | 기본 |
|---|---|---|
| 대화 (`deviceSession`) | 폰과 함께: 폰 앱 대화와 한 세션 / 공기계끼리: 공기계들이 한 세션 / 기기마다: 기기별 세션 | 폰과 함께 |
| 답하는 곳 (`deviceReply`) | 들은 기기 / 폰 / 둘 다 | 들은 기기 |
| 개인적인 내용 (`devicePrivacy`) | 그대로 말하기 / 소리로 말하지 않기 / 폰으로 보내기 | 그대로 말하기 |
| 도구 (`deviceTools`) | 전체: 폰 앱 대화와 같음 / 노트·말하기·조명만 | 전체 |
| 내 MCP (`deviceMcp`) | 폰 앱만 / 공기계도 | 폰 앱만 |
| 새 대화 (`deviceIdleMin`) | 5분, 10분, 30분 조용하면 / 끄기 | 10분 |

- "폰과 함께"면 공기계에서 한 말이 폰 앱 대화의 한 턴이 된다. 폰 앱 대화는 지금처럼 이어지므로 "새 대화"는 적용되지 않고, 도구도 항상 전체다
- "공기계끼리"와 "기기마다"는 별도 세션이다. 정한 시간 동안 조용하면 다음 말부터 새 대화로 시작한다
- 폰 앱 대화에 들어간 공기계 턴과 폰으로 온 답은 폰 앱 화면에 "거실에서"처럼 출처를 달고 보인다
- 개인적인 내용의 판단은 에이전트가 한다. 턴 앞에 붙는 표시(`[기기: 거실, 개인 정보: 폰으로]`)를 보고 따른다. "폰으로 보내기"는 `send_to_phone` 도구로 폰 앱에 보낸다
- 도구가 "전체"면 공기계에 말하는 누구나 명령을 실행시킬 수 있다. 집 안 기기를 혼자 쓴다는 가정이다. 손님이 오거나 TV 소리가 걱정되면 "노트·말하기·조명만"으로 바꾼다
- "내 MCP" 는 사용자가 Pi 에 붙인 MCP 서버다(pi-mcp-adapter, Claude Code 등에서 가져온 것 포함). 메일, 저장소, 브라우저처럼 멀리 닿는 것이 많아서 기본은 폰 앱에서만 쓴다. 까치 확장이 턴마다 머리말을 보고 공기계 턴에서는 그 도구들을 끄고 폰 앱 턴에서 다시 켠다. "폰과 함께" 세션에서도 마찬가지다. `kkachi.mcp.json` 에 넣은 서버(기기, 기억, HA)는 까치 자신의 도구라 이 설정과 상관없이 "도구" 설정을 따른다

## 세션과 커밋

- 폰 앱 턴은 지금처럼 새 메시지가 앞 턴을 멈춘다. 공기계 턴은 멈추지 않고 차례를 기다린다
- 도구가 "전체"인 공기계 턴은 폰 앱 턴과 같은 줄에 서고, 끝나면 core 가 턴 하나를 커밋 하나로 만든다. 같은 레포를 동시에 고치지 않기 위해서다
- 도구가 "노트·말하기·조명만"이면 노트는 `memory_*` 도구로만 바뀌고 바꿀 때마다 커밋된다. 폰 앱 턴을 기다리지 않는다
- 모든 공기계 턴은 30분 대화 정리에 `[거실] …`로 들어간다

## 폰 앱 피드

폰 앱은 열려 있는 동안 `/api/feed` 를 듣는다. 공기계 턴(폰과 함께이거나, 답하는 곳에 폰이 들어갈 때)과 `send_to_phone` 메시지가 온다. 마지막으로 본 번호를 기억해 두었다가 다시 열 때 그 뒤의 것만 받는다. 피드는 서버 메모리에 최근 100개만 두고, 서버가 재시작하면 비워진다. 답하는 곳에 폰이 들어간 항목은 폰의 읽어 주기가 켜져 있으면 소리로도 읽는다.
